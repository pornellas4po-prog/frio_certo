## Story

**Como** dono do sistema,
**quero** que todas as chamadas à uazapi passem pelo backend,
**para** proteger o token administrativo e os tokens das instâncias.

## Acceptance Criteria

1. Tabela de instâncias no Supabase (com RLS) guardando nome, número, ID e token da instância na uazapi, status, QR Code, webhook configurado e nome do perfil conectado.
2. Backend Python com as operações: criar, conectar, ver status, desconectar e excluir instância.
3. O token administrativo fica só em variável de ambiente (`UAZAPI_ADMIN_TOKEN`); o token da instância nunca vai para o navegador (NFR10).
4. Operações de instância registradas em log de auditoria.

## Dev Notes

**Origem:** PRD v0.3, História 2.1 · `docs/architecture.md` §18 (2.1) · épico [EP02](../prd/epic-02-whatsapp-e-caixa.md).

- Colunas (arquitetura §6): nome, numero, uazapi_instance_id, token (**só backend/worker**), status, qr_code, webhook_configurado, perfil_nome, ia_ativa.
- API (§8): `POST /whatsapp/instancias`, `POST /{id}/conectar`, `GET /{id}/status`, `POST /{id}/desconectar`, `DELETE /{id}`, `PATCH /{id}`.
- Header do token admin: `admintoken`, minúsculo e sem "Bearer" (`docs/Uazapi/configuracao-instancia-uazapi.md`); endpoints finais vêm de `docs/Uazapi/contrato-validado.md` (Story 1.7).
- Segurança: §14 (tokens nunca no navegador; `audit_log` para operações de instância).

**Não inventar (Constituição, Art. IV):** o que não estiver no PRD ou na arquitetura vira pergunta ao dono.
